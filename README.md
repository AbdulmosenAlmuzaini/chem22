# دليل نشر منصات كيمياء 2-2 على Cloudflare Pages مع قاعدة البيانات D1

إعداد المعلمة: صباح داخل الأحمدي - الثانوية السادسة والثلاثون بالمدينة المنورة

---

## أولًا: ماذا يحتوي المشروع؟

| المجلد أو الملف | محتواه |
|---|---|
| `public/index.html` | الصفحة الرئيسة: بطاقات الفصول الستة |
| `public/ch1/` إلى `public/ch6/` | منصات الفصول الستة |
| `public/teacher/` | لوحة متابعة المعلمة (لا يظهر لها رابط للطالبات) |
| `functions/api/progress.js` | يحفظ تقدم الطالبة في قاعدة البيانات |
| `functions/api/results.js` | يعرض النتائج للمعلمة ويحذفها (محمي بكلمة مرور) |
| `functions/api/chat.js` | «اسألي مساعدك الكيميائي» عبر OpenRouter |
| `lib/rules.js` | تعليمات المساعد لكل فصل |
| `schema.sql` | أمر إنشاء جدول قاعدة البيانات |
| `wrangler.toml.example` | للاستخدام من سطر الأوامر فقط (اختياري) |

بعد النشر تكون الروابط هكذا (مثال):

- الصفحة الرئيسة: `https://chem22.pages.dev/`
- الفصل الأول: `https://chem22.pages.dev/ch1/` … حتى `ch6`
- لوحة المعلمة: `https://chem22.pages.dev/teacher/`

## ثانيًا: ما الذي تغيّر عن نسخة claude.ai؟

1. **حفظ التقدم في قاعدة بيانات حقيقية:** في الصفحة الرئيسة لكل فصل قسم «تقرير التقدم للمعلمة». تكتب الطالبة اسمها وتضغط «☁️ احفظي تقدمي لدى المعلمة» مرة واحدة، وبعدها يُحدَّث تقدمها تلقائيًا كلما أنجزت مهمة أو اختبارًا.
2. **لوحة المعلمة تقرأ من قاعدة البيانات مباشرة،** وزر «🔄 تحديث من قاعدة البيانات» يجلب أحدث النتائج. وما زال لصق «رموز التقدم» متاحًا احتياطًا.
3. **المساعد الكيميائي** يعمل عبر مفتاح OpenRouter المحفوظ في إعدادات Cloudflare، ولا يظهر المفتاح في أي صفحة.
4. **قاعدة البيانات لا تُمسح عند تحديث الموقع:** يمكنك رفع نسخ جديدة من الصفحات متى شئت، وتبقى نتائج الطالبات محفوظة.

## ثالثًا: ما تحتاجينه قبل البدء

- حساب مجاني في **Cloudflare**: https://dash.cloudflare.com/sign-up
- حساب مجاني في **GitHub**: https://github.com/signup
- (اختياري لتفعيل المساعد) مفتاح من **OpenRouter**: https://openrouter.ai/keys

> ⚠️ **تنبيه أمني:** مفتاح OpenRouter القديم الذي كُتب سابقًا في المحادثة مكشوف. ادخلي https://openrouter.ai/keys واحذفيه (Delete)، ثم أنشئي مفتاحًا جديدًا ولا تكتبيه في أي ملف أو رسالة.

## الخطوة 1: إنشاء قاعدة البيانات D1

1. ادخلي https://dash.cloudflare.com وسجّلي الدخول.
2. من القائمة الجانبية اختاري **Storage & Databases** ثم **D1 SQL Database**.
3. اضغطي **Create** (أو Create database).
4. اكتبي الاسم: `chem22-db`، واتركي الموقع (Location) تلقائيًا، ثم اضغطي **Create**.

## الخطوة 2: إنشاء جدول النتائج

1. افتحي قاعدة البيانات `chem22-db` التي أنشأتِها.
2. اختاري تبويب **Console**.
3. افتحي ملف `schema.sql` من المشروع، وانسخي محتواه كاملًا، والصقيه في مربع الأوامر.
4. اضغطي **Execute**.
5. للتأكد: اكتبي الأمر الآتي واضغطي Execute، ويجب أن يظهر اسم الجدول `progress`:

```sql
SELECT name FROM sqlite_master WHERE type='table';
```

## الخطوة 3: رفع المشروع إلى GitHub

1. فكّي ضغط الملف `chem22-cloudflare.zip` على جهازك.
2. ادخلي GitHub واضغطي **+** أعلى الصفحة ثم **New repository**.
3. اكتبي الاسم: `chem22`، واختاري **Private** (خاص)، ثم **Create repository**.
4. في الصفحة التالية اضغطي الرابط **uploading an existing file**.
5. اسحبي **محتويات** المجلد بعد فك الضغط (المجلدات `public` و `functions` و `lib` والملفات الأخرى)، وليس المجلد نفسه.
   - المهم أن يظهر في المستودع مباشرة: `public/` و `functions/` و `lib/` و `schema.sql`.
6. اضغطي **Commit changes**.

> 💡 إن لم يقبل المتصفح سحب المجلدات، استعملي برنامج **GitHub Desktop** (مجاني): انسخي الملفات إلى مجلد المستودع ثم اضغطي Commit ثم Push.

## الخطوة 4: إنشاء موقع Cloudflare Pages وربطه بـ GitHub

1. في Cloudflare اختاري **Workers & Pages** ثم **Create** ثم تبويب **Pages**.
2. اختاري **Connect to Git** (أو Import an existing Git repository)، وسجّلي الدخول إلى GitHub، واسمحي لـ Cloudflare بالوصول إلى المستودع `chem22`.
3. اختاري المستودع `chem22` ثم **Begin setup**.
4. اضبطي الإعدادات هكذا:
   - **Project name:** `chem22` (سيصبح الرابط chem22.pages.dev، ويمكنك اختيار اسم آخر)
   - **Production branch:** `main`
   - **Framework preset:** `None`
   - **Build command:** اتركيه فارغًا
   - **Build output directory:** `public`
5. اضغطي **Save and Deploy**، وانتظري حتى تظهر رسالة النجاح.

> ملاحظة: طريقة «رفع الملفات مباشرة» (Upload assets / سحب المجلد) لا تشغّل مجلد `functions`، لذلك يلزم الربط بـ GitHub كما في هذه الخطوة حتى تعمل قاعدة البيانات والمساعد.

## الخطوة 5: ربط قاعدة البيانات بالموقع (مهم جدًا)

1. افتحي مشروع `chem22` في **Workers & Pages**.
2. اختاري **Settings** ثم **Bindings** (في بعض الواجهات: Settings ← Functions ← D1 database bindings).
3. اضغطي **Add** ثم اختاري **D1 database**.
4. **Variable name:** اكتبي `DB` بالأحرف الكبيرة تمامًا كما هي.
5. **D1 database:** اختاري `chem22-db`.
6. اضغطي **Save**.
7. كرري الربط نفسه لبيئة **Preview** إن ظهرت لك (اختياري).

## الخطوة 6: إضافة كلمة مرور المعلمة ومفتاح المساعد

1. في المشروع نفسه: **Settings** ثم **Variables and Secrets**.
2. اضغطي **Add** وأضيفي:

| الاسم (Variable name) | النوع | القيمة |
|---|---|---|
| `TEACHER_PASSWORD` | Secret | كلمة مرور لوحة المعلمة (إن لم تضيفيها تكون 123456) |
| `OPENROUTER_API_KEY` | Secret | مفتاح OpenRouter الجديد (لتفعيل المساعد) |
| `OPENROUTER_MODEL` | Text (اختياري) | `anthropic/claude-haiku-4.5` أو أي نموذج آخر من openrouter.ai/models |

3. اضغطي **Save**.

> 🔐 ننصح بتغيير كلمة المرور الافتراضية 123456 إلى كلمة خاصة بك، لأنها كُتبت في المحادثة.

## الخطوة 7: إعادة النشر لتفعيل الإعدادات

الإعدادات الجديدة لا تعمل إلا بعد نشر جديد:

1. افتحي تبويب **Deployments** في المشروع.
2. عند آخر نشر اضغطي **⋯** ثم **Retry deployment**.
3. انتظري حتى يكتمل النشر.

## الخطوة 8: التجربة

1. افتحي `https://اسم-مشروعك.pages.dev/` وادخلي أي فصل.
2. في أسفل الصفحة الرئيسة للفصل، في قسم «تقرير التقدم للمعلمة»، اكتبي اسمًا ثلاثيًا واضغطي «☁️ احفظي تقدمي لدى المعلمة». يجب أن تظهر رسالة «✓ حُفظ تقدمك».
3. افتحي `https://اسم-مشروعك.pages.dev/teacher/` وأدخلي كلمة المرور. يجب أن تظهر رسالة «✓ متصلة بقاعدة البيانات» والاسم في الجدول.
4. افتحي المساعد الكيميائي (الزر الأخضر) واسأليه سؤالًا للتأكد من عمله.
5. احذفي الاسم التجريبي من اللوحة بزر ✕.

## المحافظة على قاعدة البيانات

- **لا تحذفي قاعدة البيانات `chem22-db`** ولا تغيّري اسم الربط `DB`، فبهما ترتبط النتائج بالموقع.
- **تحديث الصفحات لا يمسح النتائج:** عدّلي ملفات `public` في GitHub وسيُعاد النشر تلقائيًا مع بقاء البيانات.
- **نسخة احتياطية من لوحة المعلمة:** زر «⬇️ تنزيل النتائج (CSV)» ينزّل ملفًا يُفتح في Excel.
- **نسخة احتياطية كاملة من Cloudflare (اختياري لمن تستعمل سطر الأوامر):**
  `npx wrangler d1 export chem22-db --remote --output=backup.sql`
- **حدود الخطة المجانية:** تكفي لمدرسة بسهولة.

## تعديل المحتوى لاحقًا

- لتعديل فصل: عدّلي الملف `public/chN/index.html` في GitHub (زر القلم ✏️) ثم Commit، فيُعاد النشر تلقائيًا خلال دقيقة.
- لتعديل تعليمات المساعد: عدّلي `lib/rules.js`.
- روابط المهام الأدائية موجودة داخل كل ملف فصل في السطر `const TASK_FORM=`.

## حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| رسالة «تعذّر الحفظ الآن» عند الطالبة | تأكدي من ربط D1 باسم `DB` (الخطوة 5) وإعادة النشر (الخطوة 7)، ومن تنفيذ `schema.sql` (الخطوة 2). |
| اللوحة تقول «تعمل اللوحة دون قاعدة بيانات» | تأكدي أنك تفتحينها من رابط Cloudflare وليس من ملف على الجهاز، ثم راجعي الخطوتين 5 و 7. |
| «الرمز السري غير صحيح» مع أنه صحيح | إن غيّرتِ `TEACHER_PASSWORD` فأعيدي النشر، واكتبي الكلمة دون مسافات. |
| المساعد يقول «غير مفعّل بعد» | أضيفي `OPENROUTER_API_KEY` ثم أعيدي النشر، وتأكدي من وجود رصيد في حساب OpenRouter. |
| الصفحة تظهر 404 | تأكدي أن **Build output directory** هو `public`، وأن مجلد `public` في جذر المستودع. |
| ظهر اسم الطالبة مرتين بصيغتين | يُفرّق النظام بين «نورة محمد» و«نوره محمد». اطلبي من الطالبات كتابة الاسم بالصيغة نفسها في كل الفصول، واحذفي المكرر من اللوحة. |

## ملاحظات خصوصية

- لا تُحفظ في قاعدة البيانات إلا: اسم الطالبة، ورقم الفصل، وعدد الدروس المنجزة، ونتيجة الاختبار الختامي، والنجوم، ووقت التحديث.
- لوحة المعلمة لا تعرض البيانات إلا بكلمة المرور، والتحقق يتم في الخادم.
- اجعلي مستودع GitHub **خاصًا (Private)**.
